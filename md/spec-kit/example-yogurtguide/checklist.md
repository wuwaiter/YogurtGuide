| 欄位 | 值 |

| 名稱 | YogurtGuide 網站與 Android App |
| 版本 | 1.0 |
| 狀態 | 範例（依 2026-11-02 的專案現況反推，不是正式送審版本） |

## 1. 背景與目的

自製優格的人常遇到兩個問題：同一種菌粉每次做出來都不一樣，卻記不起上次的溫度與時間；市售菌粉與優格的成分、菌種資訊分散，難以比較。

YogurtGuide 用可重複的方式記錄每一批的條件與結果，並整理菌種、菌粉、市售優格的公開資料。Android App 讓使用者離線查資料，第 2 階段再加上手機端自己的發酵紀錄。

不做的後果：站主的實驗資料只留在手寫筆記，無法比較、無法分享。

## 2. 使用者與角色

| 角色 | 要達成什麼 |
|---|---|
| 站主 | 用最少步驟新增批次與資料；資料寫錯時在上線前被擋下 |
| 讀者（網站） | 找到菌粉、市售優格、做法的可信資料，知道資料的日期與限制 |
| App 使用者 | 離線看同樣的內容；第 2 階段起在手機上記錄自己的每一批 |

## 3. 範圍

**這次做**
- 網站 9 個單元：批次實驗、菌種與菌株、優格種類、菌粉、搭配、市售優格、製法、專有名詞、關於。
- Android App：內容與網站相同、可離線、內容更新不必重新上架。
- App 第 2 階段：自製優格紀錄（只存手機）。

**這次不做**
- 帳號、登入、留言、購物連結。
- iOS。
- 英文版。
- 雲端備份（列為第 3 階段，另開一份需求規格）。
- 傳代線趨勢圖、Kefir 二次發酵、匯出 Markdown。

## 4. 需求清單

### R-01 依固定順序瀏覽 9 個內容單元（P1）

- 為什麼：讀者從「自己做」到「買現成的」逐步深入，順序反映使用頻率。
- 輸入：讀者點導覽。
- 輸出：導覽依序為批次實驗、菌種與菌株、優格種類、菌粉、搭配、市售優格、製法、專有名詞、關於。
- 失敗時：不適用（固定內容）。
- 驗收：
  - AC-01-1 Given 任何頁面，When 看導覽列，Then 順序與上列相同，且名稱是「專有名詞」不是「詞彙」。
- 現況：已完成。

### R-02 記錄每一批的條件與結果（P1）

- 為什麼：一次只改一個變因，才能比較出差異。
- 輸入：日期、室溫、保溫溫度、牛奶、菌種、發酵時間、設備、凝乳／質地／酸度評分、照片。
- 輸出：批次列表與單批頁面。
- 必填：日期、保溫溫度、發酵時間、菌的來源與名稱、凝乳結果。室溫、質地、酸度等其餘欄位選填。
- 失敗時：必填欄位缺漏或日期格式錯 → 這批不上線，站主在上線前收到錯誤。
- 驗收：
  - AC-02-1 Given 一批缺少保溫溫度，When 站主發布，Then 發布失敗並指出缺的欄位。
  - AC-02-2 Given 一批是傳代第 3 次，When 讀者看該批，Then 看得到菌名與代數。
- 現況：已完成。

### R-03 菌粉資料只呈現可查證的事實（P1）

- 為什麼：避免變成業配；讀者要分得出「查不到」與「沒有」。
- 輸入：一筆菌粉資料。
- 輸出：包裝圖、規格、菌種、價格、評價。
- 失敗時：
  - 沒有評價 → 「沒有評價資訊」。
  - 沒有菌種 → 「沒有菌種資訊」。
  - 沒有包裝圖 → 「本輪未取得包裝圖」。
- 限制：不放店名與購買連結；價格只留金額、幣別、單位、日期。
- 驗收：
  - AC-03-1 Given 一筆菌粉沒有菌種資料，When 打開菌粉頁，Then 該卡片顯示「沒有菌種資訊」。
  - AC-03-2 Given 任何菌粉，When 檢視卡片，Then 找不到店名或購買連結。
- 現況：已完成。

### R-04 市售優格依成分與營養標示給推薦星等（P1）

- 為什麼：讓讀者一眼分辨「只有奶與菌」的產品。
- 輸入：成分標示、每 100 g（或 100 ml）的熱量、蛋白質、脂肪、碳水、糖。
- 輸出：0–3 顆星與各項數字。
- 規則：
  - ★：成分只有鮮乳／生乳、奶粉＋水、菌種、菌種載體（乳糖、寡糖粉、麥芽糊精、奶粉；含澱粉不算）、益生元。
  - ★★：★ 且蛋白質 ≥ 7 g。
  - ★★★：★★ 且脂肪 ≤ 3 g，且碳水 ≤ 5 g 或糖 ≤ 3 g。
  - 每 100 g 視同每 100 ml。
- 失敗時：查不到營養標示 → 最多 ★，數字欄顯示「—」；全部查不到 → 「營養標示：沒有營養標示資訊」。
- 驗收：
  - AC-04-1 Given 菌種載體含玉米澱粉，When 評星，Then 0 顆星。
  - AC-04-2 Given 蛋白質 7.0 g、脂肪 3.0 g、糖 3.0 g 且成分合格，When 評星，Then ★★★（邊界值算通過）。
- 現況：已完成。

### R-05 隔夜燕麥的份量要嘛完整、要嘛不寫（P2）

- 為什麼：只寫數字沒有單位，讀者會照錯。
- 輸入：食材名稱、份量、份量上限、單位。
- 輸出：「食材／份量」表。
- 規則：單位只能是 g、ml、顆、湯匙；有份量就要有單位；範圍用份量上限。
- 失敗時：有份量沒單位、或單位不在清單 → 不能發布。
- 驗收：
  - AC-05-1 Given 份量 30、單位空白，When 發布，Then 發布失敗。
- 現況：已完成。

### R-06 內容錯誤在上線前被擋下（P1）

- 為什麼：站主一個人維護，沒有人幫忙校稿。
- 輸入：站主修改的內容。
- 輸出：發布成功，或列出錯誤的檔案與欄位。
- 失敗時：任何格式錯誤、測試失敗、疑似秘密 → 整次不上線，網站維持上一版。
- 驗收：
  - AC-06-1 Given 一筆資料欄位格式錯，When 發布，Then 網站仍是上一版。
- 現況：已完成。

### R-07 App 離線可讀，內容更新不必重新上架（P1）

- 為什麼：重新上架要審核，內容卻幾乎每天改。
- 輸入：網站發布新版。
- 輸出：App 背景下載新內容，下次開啟生效。
- 失敗時：
  - 下載失敗或內容損壞 → 繼續用目前版本。
  - 新內容開不起來 → 自動退回上一版。
  - 新內容需要較新的 App → 不套用，等使用者更新 App。
- 驗收：
  - AC-07-1 Given 手機離線，When 開啟 App，Then 看得到上次下載的全部文字內容。
  - AC-07-2 Given 網站已發布新版，When 使用者開兩次 App，Then 第二次看到新內容。
- 現況：已完成（照片仍在 App 內容包裡，見 R-08）。

### R-08 App 的照片從網站讀，不打包（P2）

- 為什麼：內容包 9.0 MB 中照片佔 8.3 MB，改一個字就要整包重下載。
- 輸入：App 顯示一張包裝圖。
- 輸出：從網站讀取並快取 30 天的照片。
- 失敗時：離線且沒有快取 → 顯示圖片說明文字，版面不跑掉。
- 限制：換照片要換檔名，避免看到舊圖。
- 驗收：
  - AC-08-1 Given 離線且沒看過某張圖，When 打開那張卡片，Then 顯示說明文字，卡片高度不變。
- 現況：已決定，未實作。

### R-09 App 使用者記錄自己的發酵（P1，第 2 階段）

- 為什麼：讓站主以外的人也能用同一套方法比較每一批。
- 輸入：發酵類型（菌粉／市售優格、傳代、可傳代母菌、Kefir）、菌的來源、時間、評分（1–10）、最多 4 張照片。
- 輸出：紀錄列表、進行中置頂、傳代線。
- 規則：
  - 選「上一代」時帶入菌名、代數 +1、上次溫度與時間。
  - 紀錄名稱自動產生：`菌名*代數 (起始日)`，符號一律半形。
  - 「上一代」建立後不能改；第一版不提供刪除，只能隱藏。
- 失敗時：儲存中斷 → 這筆整筆不存在，不留半筆；照片存失敗 → 整筆不存並提示。
- 驗收：
  - AC-09-1 Given 一筆第 2 代紀錄，When 選它當上一代，Then 新紀錄是第 3 代且菌名相同。
  - AC-09-2 Given 一筆紀錄被隱藏，When 看首頁，Then 不顯示，但它的下一代仍看得到傳代關係。
- 現況：未開始。

### R-10 發酵時間到提醒（P1，第 2 階段）

- 為什麼：發酵常跨夜，忘記看就過酸。
- 輸入：按「開始發酵」的時間、預計時間（Kefir 自選，預設 24 小時）。
- 輸出：時間到的通知；Kefir 可一鍵延後 4 小時。
- 失敗時：使用者拒絕通知權限 → 紀錄照常運作，紀錄頁顯示剩餘時間，並說明不會收到通知。
- 驗收：
  - AC-10-1 Given 沒有通知權限，When 開始發酵，Then 紀錄建立成功且看得到剩餘時間。
- 現況：未開始。

### R-11 公開資訊與授權清楚（P2）

- 為什麼：照片與字體有著作權；使用者要知道資料怎麼處理。
- 輸出：隱私權頁、開放原始碼授權頁（套件與字體）。
- 規則：照片只用自拍或有授權的；來源不明的照片移除。
- 驗收：
  - AC-11-1 Given 任何一張網站照片，When 查來源，Then 是自拍或授權頁列得到。
- 現況：已完成。

## 5. 資料項目

| 項目 | 說明 | 唯一識別 | 關係 |
|---|---|---|---|
| 批次 | 站主的一次發酵 | 批次編號（b001…） | 記菌名與代數，不連到上一批；可引用菌種、製法 |
| 菌種 | 一種菌與其特性 | 名稱 | 被菌粉、優格種類引用 |
| 優格種類 | 一種發酵乳的來源與條件 | 名稱 | 引用菌種 |
| 菌粉 | 一款市售菌粉 | 產品代號 | 引用菌種 |
| 市售優格 | 一款市售優格 | 產品代號 | 無 |
| 搭配 | 食材、益生元、隔夜燕麥 | 名稱 | 燕麥引用食材 |
| App 紀錄 | 使用者的一次發酵（第 2 階段） | 紀錄代號 | 可指向上一代；引用菌粉或市售優格時存代號＋當時名稱 |

- App 紀錄引用的菌粉下架或改名時，舊紀錄仍顯示當時的名稱。

## 6. 狀態與順序

**App 紀錄（第 2 階段）**

```
建立 → 發酵中 → 冷藏中 → 完成
              ↘（任何階段）隱藏 ⇄ 取消隱藏
```

- 只能往前，不能從「完成」回到「發酵中」。
- 「移入冷藏」之前不能評分。
- 時間由按鈕自動記錄，不手填；修改時間不能早於前一個階段。

**內容發布**

```
修改內容 → 檢查（格式、測試、秘密）→ 建置 → 上線 → App 下次開啟取得
```

- 檢查沒過，後面全部不做。

## 7. 邊界條件

| 編號 | 情況 | 結果 |
|---|---|---|
| E-01 | 必填欄位空白 | 不能發布／不能儲存，指出欄位 |
| E-02 | 評分 0、11、小數 | 只接受 1–10 整數 |
| E-03 | 份量為 0 或負數 | 不能發布 |
| E-04 | 照片第 5 張 | 不能加入，提示上限 4 張 |
| E-05 | 「開始發酵」連按兩次 | 只記第一次 |
| E-06 | 跨午夜、跨月的發酵 | 時間以台灣時間（UTC+8）計算與顯示 |
| E-07 | 手機時間被調過 | 剩餘時間可能不準；以裝置時間為準，不另外校時（假設） |
| E-08 | 離線 | 文字照常；沒快取的照片顯示說明文字 |
| E-09 | 網站暫時連不上 | App 繼續用目前內容，不顯示錯誤 |
| E-10 | 代數超過 99 | 照常加 1，不設上限（假設） |

## 8. 非功能需求

| 編號 | 需求 |
|---|---|
| NFR-01 | 離線：App 所有文字內容離線可讀 |
| NFR-02 | 隱私：網站不收個人資料；App 紀錄與照片只存在手機，不上傳 |
| NFR-03 | 敏感資料：簽章金鑰、部署憑證不得進入版本控制、建置記錄或網站 |
| NFR-04 | 語言：只有繁體中文；專業術語附英文 |
| NFR-05 | 資料時效：每筆市售資料附查詢日期 |
| NFR-06 | 照片：壓縮到長邊 1600 px、約 300 KB |
| NFR-07 | 權限：只在需要時請求（通知權限在引導第 3 頁才請求） |
